# 频率与时序验证

使用Vivado 2019.2、器件`xc7a35tcsg324-1`完成布局布线后时序检查。

| 对象 | 目标频率 | 周期 | WNS | 结论 |
| --- | ---: | ---: | ---: | --- |
| 单周期CPU核心与片上存储器包装 | 50 MHz | 20 ns | +6.080 ns | 满足时序 |
| 流水线CPU核心与片上存储器包装 | 50 MHz | 20 ns | +5.984 ns | 满足时序 |
| 流水线完整整机（Clocking Wizard、ROM、RAM、UART） | 50 MHz | 20 ns | +6.527 ns | 满足时序，bit流已生成 |

完整整机的Clocking Wizard由板载100 MHz生成50 MHz，UART参数改为`BIT_CYCLES=434`，仍对应约115200波特率。50 MHz bit流见`pipeline_50mhz_full_system.bit`。

本次自动下载时未发现JTAG目标，因此尚未完成50 MHz板上功能复查。当前证据能够证明布局布线后的时序收敛，不能替代板上串口功能验证。

## 性能表述边界

- 单周期核心和流水线核心均满足50 MHz，所以不能通过任意降低单周期频率来声称流水线本身拥有更高最高频率。
- F3中的10 MHz单周期与50 MHz流水线属于配置频率对比；五元素排序对应9.40 us与4.46 us，配置加速比2.11。
- 若采用同一50 MHz，单周期为1.88 us，流水线预测开启为4.46 us；当前流水线因83个暂停周期和填充开销反而更慢。
- 若要证明流水线结构本身提高最高频率，需要进一步优化当前执行级到PC的重定向关键路径，并分别测量两种CPU的最高收敛频率。
