## 2. 开始 M3 前需要处理的问题

### 2.1 立即数逻辑运算错误，优先修复

定位 `cpu/pipeline/src/pipeline_cpu.v` 第 66 行附近的 `ex_result`。目前只有 ADD 路径选择 `idex_imm`，OR 和 AND 始终使用 `idex_b`。但 I 型指令的相应编码位不是 rs2，寄存器值既不是立即数，也没有相应依赖保护。

实际运行以下代码，x2 得到 18，x3 得到 0，预期分别为 31、2：

```asm
addi x1, x0, 18
ori  x2, x1, 15
andi x3, x1, 15
```

这会直接影响 UART STATUS 的位掩码判断。统一选择第二操作数，所有 ALU 运算使用同一根线：

```verilog
wire [31:0] ex_operand_b = idex_alu_src ? idex_imm : idex_b;
// ex_result 对 ADD/SUB/OR/XOR/AND 分别使用 idex_a 与 ex_operand_b。
```

保留 store 数据和分支比较使用原始 `idex_b`。不要将它们一并替换为立即数。原单周期 `Top.v` 已在 ALU 前做选择，可以参考其结构。

### 2.2 规范非法指令检测和程序结束

当前程序首字是 `00000000`，短 ROM 后续填零，程序也没有显式终止循环。直接加非法指令断言会让旧排序测试立即失败。

- 工作副本首字改为真正的 `00000013`，并确认其余机器码与汇编对应；原始参考资料保持原样。
- 工作 ROM 未使用区域填 `00000013`，程序末尾增加 `jal x0,0`；测试以专用完成 PC 的首次退休结束计数，不能把死循环计入工作量。
- 数据初始化文件目前为 1024 个字，实际 RAM 为 256 个字，裁剪工作副本到 256 个字；短指令文件用明确读取范围或完整填充消除初始化告警。
- 仿真断言条件采用 `resetn && !halted && !mem_fault && !redirect && !stall && ifid_valid && dec_illegal`。接入 M3 前去掉尚不存在的故障条件，接入后补回。错误路径上的非法编码不能误报。
- 断言放在 synthesis translate_off/on 范围内；合法测试遇到非法指令调用 `$fatal`，专门的非法用例由运行脚本核对预期错误。
- 各测试 FAIL/TIMEOUT 应返回失败，不能只 `$display` 后正常结束。

M3 只增加数据地址故障，不扩展成完整非法指令硬件陷阱或指令地址异常系统。

## 5. 第二步：地址检查与停机，预计 60–90 分钟

先做故障，是因为它决定哪些年轻指令能进入 WB，后续溢出和分支统计都依赖这一条件。

`address_guard` 接口固定为 `input [31:0] addr`、`output bad`、`output [1:0] reason`，无时钟。仅在 CPU MEM 确实是有效 lw/sw 时使用输出。

```verilog
wire aligned = (addr[1:0] == 2'b00);
wire mapped = (addr < 32'h00000400) ||
              (addr == 32'h40000000) || (addr == 32'h40000004) ||
              (addr == 32'h40000008) || (addr == 32'h4000000c);
assign bad = !aligned || !mapped;
assign reason = !aligned ? 2'd1 : (!mapped ? 2'd2 : 2'd0);
```

CPU 新增 `fault_valid`、`fault_pc[31:0]`、`fault_addr[31:0]`、`fault_reason[1:0]` 输出。用 `fault_valid` 作为持久停机状态，避免两份状态不一致。

- [ ] 单测地址 0、3FC 和四个 MMIO 地址均合法；2、3FF 为原因 1；400、80000000、40000010 为原因 2；40000011 同时非法时返回原因 1。
- [ ] `raw_mem_access = exmem_valid && (exmem_mem_write || exmem_wb_sel==WB_MEM)`；`mem_fault = raw_mem_access && bad && !fault_valid`。
- [ ] `dmem_valid = resetn && raw_mem_access && !bad && !fault_valid`，`dmem_write = dmem_valid && exmem_mem_write`。地址检查必须在总线副作用之前生效。
- [ ] 在每个非复位时钟沿先保留旧 MEM/WB 的真实退休和写回，然后处理故障。故障时清 `memwb_valid/exmem_valid/idex_valid/ifid_valid`，保存 `exmem_pc/exmem_alu/reason` 并保持 PC。
- [ ] 后续停机周期保持所有 valid 为 0，不重复退休、不再访问总线；仅复位清故障和恢复 PC=0。
- [ ] 有效非法 store 不写 RAM/UART；非法 load 不写 rd、不退休；前一条 WB 指令仍完成，后续 store、branch 均被清除。
- [ ] 测试“MEM 故障与 EX 跳转同周期”时以故障为准；停机等待 20 拍确认无副作用，复位后确认可重新运行。
- [ ] 自检通过后提交一次。

合法地址上的只读写入仍由 system_env 忽略，不增加“权限故障”。若之后修改地址表，CPU guard 和 system_env 必须一起更新。

## 6. 第三步：溢出检测及 MMIO 状态，预计 45–75 分钟

`overflow_detect` 接口为 `input [31:0] a,b,result`、`input is_sub`、`output overflow`，纯组合模块：

```verilog
assign overflow = is_sub ? ((a[31] ^ b[31]) & (result[31] ^ a[31]))
                         : (~(a[31] ^ b[31]) & (result[31] ^ a[31]));
```

- [ ] CPU 在 ID 明确标记仅 `add/sub/addi` 为 `overflow_eligible`，随指令进入 EX。不能只判断 ALU_ADD，因为 lw/sw 地址计算也使用 ADD。
- [ ] EX 用 `idex_a`、`ex_operand_b`、`ex_result` 计算，`eligible` 与结果一起进入 EX/MEM、MEM/WB；事件仅在 WB 有效退休时更新粘滞状态。
- [ ] 新增 `overflow_flag` 输出，复位清零；普通指令不清零，结果保留低 32 位。即使目的寄存器是 x0，有效退休的算术溢出仍计入。
- [ ] 依次验证 7FFFFFFF+1→80000000、80000000−1→7FFFFFFF、80000000+FFFFFFFF→7FFFFFFF 均溢出，1+2 不溢出；再检查地址加法不设置标志。
- [ ] 分支错误路径上的溢出不设置标志；较老 MEM 故障杀死年轻 EX 溢出；较老 WB 溢出遇到年轻 MEM 故障时仍可设置。
- [ ] 接 `system_env.overflow_flag`，检查读 4000000C 的 bit0，写该地址无效。

特别检查“溢出指令后紧接读取状态”。当算术指令在 WB、状态 load 在 MEM 时，单纯用时序 sticky 输出会让 load 采到旧值。无需增加通用寄存器前递，可以把对外可见状态定义为：

```verilog
wire wb_overflow_event = memwb_valid && memwb_overflow;
assign overflow_flag = resetn && (overflow_sticky || wb_overflow_event);
// overflow_sticky 在时钟沿吸收 wb_overflow_event，复位清零。
```

WB 事件来自已经排除故障和冲刷的有效指令；MEM 的年轻故障不能撤销更老 WB 的事件。让 `status_mmio_tb` 预先准备好 MMIO 基址，再用无寄存器依赖的“溢出→lw 状态”验证 bit0=1，避免暂停偶然掩盖问题。

- [ ] 溢出和真实 MMIO 读取测试通过后提交一次。

## 7. 第四步：BTFNT 与统计，预计 75–120 分钟

`btfnt_predictor` 参数 `PREDICT_EN=1`；输入 `pc[31:0]`、`imm[31:0]`、`is_cond_branch`；输出 `predicted_next_pc[31:0]`。只预测 beq/bne/blt/bge。

```verilog
assign predicted_next_pc = (PREDICT_EN && is_cond_branch && imm[31])
                          ? pc + imm : pc + 32'd4;
```

CPU 顶层同样暴露 `PREDICT_EN` 并传入模块。`jal` 保持 EX 跳转处理，不计条件分支统计。

- [ ] 在 ID 计算预测，只在 ID 指令实际进入 EX 时采用；有 stall 时 PC 和 IF/ID 保持，不重复预测跳转。
- [ ] 将 `predicted_next_pc` 写入 ID/EX。ID 预测转移时，将 PC 改为预测目标并清 IF/ID；当前分支仍进入 ID/EX。这个时刻 IF 取到的仍是顺序指令，不能误标有效。
- [ ] EX 对条件分支计算 `actual_next_pc = ex_take ? idex_pc+idex_imm : idex_pc+4`；与携带的预测值比较，不同才纠正。替换旧的“只要 take 就 redirect”，否则预测正确也会重复冲刷。
- [ ] EX 纠正清 IF/ID 和 ID/EX，当前分支正常进入 EX/MEM；`jal` 仍直接重定向。
- [ ] 条件分支标记、预测错误标记随指令走到 WB；在 `memwb_valid` 时分别更新 `branch_count[31:0]`、`mispredict_count[31:0]`，复位清零。故障杀死的年轻分支不计数。
- [ ] 统一控制优先级为复位 → 已停机/本拍 MEM 故障 → EX 纠正 → 数据暂停 → ID 预测转移 → 正常取指；旧 WB 的退休单独保留。

定向程序至少包括下表。每个测试用有上界的循环，核对寄存器、总线写入和统计，不能只看最终数组。

| 用例 | PREDICT_EN=1 的预期 |
| --- | --- |
| x1 从 3 每次减 1，随后 `bne x1,x0,loop` 回跳 | 3 次条件分支，结果 T/T/N，1 次预测错误 |
| 向前条件成立跳过一条 store | 1 次条件分支、1 次错误，被跳过 store 不发生 |
| 向前条件不成立 | 1 次条件分支、0 次错误，顺序路径发生 |
| 分支依赖前一条 addi/lw | 等待期间 PC 稳定，分支只发射一次 |
| jal 跳过 store 并写链接寄存器 | store 不发生，链接为 PC+4，条件统计不增加 |
| 错误路径包含分支、溢出、非法数据访存 | 三种年轻指令均无可见事件 |
| MEM 故障和 EX 条件分支同时出现 | 分支不退休、不计数，故障停机 |

关闭预测再运行上述 3 次回跳，分支次数仍为 3，预测错误为 2。分别运行排序和相关性回归，开启/关闭预测的最终数据与有效指令语义相同；周期数允许不同，不要求一定加速。

- [ ] 预测开关两种模式及组合测试通过后提交一次。

## 9. 左逸龙的实际时间安排

按当前交付质量，原先“2–3 小时”只适合模块初稿，不足以覆盖修错、集成和验证。建议预留 **5–8 小时**，分成以下连续工作段；实际用时随工具和失败情况调整。

| 工作段 | 具体动作 | 结束时必须留下 |
| --- | --- | --- |
| 第 1 段，约 1 小时 | 建实施分支，修操作数、补 ISA 与非法指令测试 | 可用的 16 指令基线和通过日志 |
| 第 2 段，约 1–1.5 小时 | 地址 guard、首故障记录、流水线清除 | 非法访问无副作用、老 WB 正常完成证据 |
| 第 3 段，约 0.75–1.25 小时 | 溢出流水信息、sticky、MMIO 读取 | 连续状态读取与冲刷测试证据 |
| 第 4 段，约 1.25–2 小时 | BTFNT 接入、纠正、分支计数 | 开关预测结果一致、定向统计正确 |
| 第 5 段，约 0.75–1 小时 | 组合回归、Vivado、文档交接 | 一个明确提交的 M3 交付版本 |

先完成一段再进入下一段。卡住 30–45 分钟就保存最小程序、失败 PC、关键 valid/redirect/fault 信号；让 AI 只分析这个反例，不同时重写流水线和测试预期。若时间不足，保留上一份通过提交，明确哪些功能未接完；不要把未通过的三功能版本作为 M6 基线。

AI 每次任务给出本文对应小节、现有 `pipeline_cpu.v`、允许修改的文件与测试预期。由 AI 写代码和运行结果后，左逸龙至少能够解释每个新增信号属于哪一级、何时有效、如何被冲刷，以及为何不会产生错误路径副作用。
