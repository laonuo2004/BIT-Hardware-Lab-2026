## 一、项目目标与分工

### 1. 固定方案

| 项目 | 方案 |
| --- | --- |
| CPU | 支持 16 条 RV32I 指令的五级流水线 CPU |
| 控制器 | 硬布线控制，使用控制表辅助 AI 生成代码 |
| 数据相关 | 硬件检测与暂停，中期和结项采用相同方案 |
| 控制相关 | 静态分支预测及预测错误恢复 |
| 外设 | 自制 UART 收发控制器 |
| 应用 | CPU 排序、串口输出结果，接收 `r` 后重新运行 |
| 三项 CPU 附加功能 | 溢出检测、静态分支预测、访存地址检查与故障记录 |
| 工具 | Vivado 2019.2、Verilog、RARS |

地址检查与故障记录归入任务书“其他”类附加功能，教师认可口径需要核实。性能统计是课程基本要求，不另外凑作附加功能。两个阶段不安排 Cache、中断、前递升级、VGA 或复杂交互界面。

### 2. 中期成果

中期前接通一套可以独立运行的系统，运行流程固定如下：

1. 复位 CPU。
2. CPU 将 `4、2、5、1、3` 写入数据 RAM。
3. CPU 执行排序。
4. UART 向电脑发送 `SORT: 1 2 3 4 5\r\n`。
5. 电脑发送字符 `r`。
6. CPU 重新初始化数组、排序并输出。

需要交付流水线 CPU、UART 收发与寄存器接口、系统连接、应用汇编与机器码、三项附加功能及测试、单周期复现结果、初步性能计数，以及两门课中期 PPT 和演示记录。

**完整系统仿真通过是内部必达目标，板上完成上述交互是正式目标。** 若仅完成仿真，汇报明确说明尚未完成上板。两个模块分别运行不等于完成系统集成，单周期与 UART 接通也不能称为流水线成果。

### 3. 结项成果

沿用中期架构，扩大测试、修复问题，完成 UART IP 封装、完整性能实验、板上稳定性测试、报告、最终 PPT、视频及个人任务。中期版本单独保存，后续修改保留可恢复的稳定版本。

三个功能分别成模块，逐项独立测试并接入流水线主体。接入依赖修复后的 M2。

#### M3.1 溢出检测

- [ ] 检测 `add、sub、addi` 的有符号溢出。
- [ ] 结果仍保留低 32 位，不增加异常跳转。
- [ ] 指令有效完成时更新粘滞标志，复位清零。
- [ ] 地址计算、空泡、被冲刷指令不更新标志。

| 自检场景 | 预期 |
| --- | --- |
| `0x7FFFFFFF + 1` | 设置溢出 |
| `0x80000000 - 1` | 设置溢出 |
| `1 + 2` | 不溢出 |
| 错误路径中的溢出运算 | 不设置标志 |

#### M3.2 静态分支预测

固定采用 BTFNT：向后条件分支预测跳转，向前条件分支预测不跳转。`jal` 单独处理，不计入条件分支统计。

1. ID 产生预测下一 PC，只有指令实际进入 EX 时执行预测重定向。
2. 预测信息随指令进入 EX。
3. EX 比较实际下一 PC 与预测下一 PC，不一致时恢复正确 PC 并清除年轻指令。
4. 条件分支有效完成时统计分支次数和预测错误次数。
5. 提供 `PREDICT_EN` 参数，关闭时按顺序取指并进行跳转恢复，供性能对比使用。

**自检：**向后跳转成立、循环结束不跳转、向前分支成立与不成立、分支操作数等待均正确；错误路径存储未执行；开关预测不改变最终结果。

#### M3.3 地址检查与故障记录

检查地址未按 4 字节对齐，以及地址不在 RAM 或约定外设寄存器中的情况。

1. 在 MEM 产生读写副作用前检查地址。
2. 故障访问不发出有效总线请求，错误加载不进入有效写回。
3. 记录首次故障 PC、地址和原因。
4. 清除年轻指令并停止取指，允许更老 WB 指令完成。
5. 复位清除故障并恢复运行。

原因编码为 `1=不对齐，2=未映射`，同时出现时优先记录不对齐。

**自检通过标准：**非法访问不破坏 RAM、不触发 UART，故障记录准确。该功能称为故障检测与停机，不称为完整异常处理系统。

## 五、统一技术约定

### 1. CPU 行为

固定 16 条指令：

```text
add sub xor addi ori lui lw sw beq bne blt bge jal and or andi
```

- `x0` 始终为零；只支持对齐的 32 位 `lw/sw`。
- 不实现 `ecall`，NOP、伪指令和标签不另计条数。
- 不采用 MIPS 分支延迟槽。
- 未支持指令不得默认执行为加法，仿真遇到时应报错。
- 指令与数据存储器分开，四组流水寄存器均有有效标志。
- 控制优先级为：复位、较老指令故障、EX 预测纠正、数据等待、ID 预测重定向、正常执行。

### 2. 跨组接口

| 信号 | 方向，相对 CPU | 含义 |
| --- | --- | --- |
| `clk` | 输入 | 系统时钟 |
| `resetn` | 输入 | 低有效复位 |
| `imem_addr[31:0]` | 输出 | 指令字节地址 |
| `imem_rdata[31:0]` | 输入 | 组合读取的指令 |
| `dmem_valid` | 输出 | 一次有效数据访问 |
| `dmem_write` | 输出 | 1 写、0 读 |
| `dmem_addr[31:0]` | 输出 | 数据字节地址 |
| `dmem_wdata[31:0]` | 输出 | 写入数据 |
| `dmem_rdata[31:0]` | 输入 | 组合读取的数据 |

存储器组合读、上升沿写，一条存储指令只产生一次有效写入。CPU 轮询 UART 状态，不增加总线等待协议。空泡、故障访问、被冲刷指令不得发出有效请求。RAM 与 UART 写使能互斥，先解码完整地址，再取 RAM 数组下标。

CPU 额外输出有效完成指令、完成 PC、写回使能、目的寄存器、写回值、溢出标志、故障有效、故障 PC、故障地址、故障原因、条件分支次数和预测错误次数，供仿真及记录使用。

### 3. 地址与 UART

| 地址 | 功能 |
| --- | --- |
| `0x00000000–0x000003FF` | 1 KiB 数据 RAM |
| `0x40000000` | UART TX，写低 8 位启动发送 |
| `0x40000004` | UART STATUS |
| `0x40000008` | UART RX，读取低 8 位并消费该字节 |
| `0x4000000C` | CPU 溢出状态，只读，bit0 为溢出标志 |

STATUS 的 bit0 为发送忙，bit1 为接收数据有效，bit2 为接收缓冲溢出，bit3 为帧错误，bit4 为发送忙时发生额外写入。错误位写 1 清除，其余位由硬件维护。

- 忙时发送新数据：丢弃新数据，设置 bit4。
- 未消费接收数据时收到新字节：保留旧字节，设置 bit2。
- 同周期消费旧字节并收到新字节：保存新字节。
- RX 无数据时读取返回零；写只读寄存器不改变状态；读取 TX 返回零。
- RX 停止位错误时丢弃该帧并记录错误。
- 复位清空状态，TX 回到空闲高电平。

通信格式为 **115200 波特率、8 位数据、无校验、1 位停止位、无流控**。系统时钟为 10 MHz，UART 每位计数 87 周期，RX 采用两级同步与位中心采样。位计数产生使能，不另造逻辑分频时钟。

Clocking Wizard 输入频率、器件与引脚由黄奕晨按实际精工板资料核对。大三工程当前记录的目标器件不能直接沿用到板上工程。

### 3. AI 使用方法

1. 提供任务编号、输入资料、接口、预期结果和允许修改的范围。
2. 明确测试场景，再生成 RTL 或脚本。
3. 实际运行 Vivado，保存输出。
4. 将首个失败、相关波形和最小程序交给 AI 定位。
5. 修改后运行相关测试和完整回归。
6. 保存代码、测试和日志，能解释本人负责的内容。

AI 不自行更换接口、指令集、时钟与地址；两组只修改自己负责的文件；不同时改实现、输入和预期来消除失败。“AI 表示通过”不能代替运行结果。报告中的数据与完成范围来自本组实际记录。
